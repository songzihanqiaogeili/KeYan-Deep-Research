# 以题找文与以文找文

2026-11-04。项目定位：以问题或种子论文为起点的研究探索与文献分析助手，辅助理解研究现状、比较方法、选择阅读路线和提出待验证思路。

## 两种入口，共用一套研究流程

| 入口 | 输入 | 主要用途 |
|---|---|---|
| 以题找文 | 研究问题、年份、排除主题、资源条件 | 从方向出发了解研究分支、代表方法和证据缺口 |
| 以文找文 | 1–3 篇种子论文，研究目标可选 | 从已有工作寻找同问题的对比研究、相近方法及继续阅读的线索 |

两种入口共用检索、元数据条件核验、相关性筛选、可访问全文获取、定向阅读、证据整理与网页报告。入口和输出方式独立：可以选择趋势调研，也可以选择论文推荐与精读。以文找文复用有界收集器；趋势模式的历史覆盖检查不强加给精读模式。

## 如何使用

1. 停止旧科研后端，再双击项目根目录 start-scientific.cmd 启动。重复点击启动器可能复用旧进程，不能代替重启。页面按 Ctrl+F5 更新静态资源。
2. 在“研究入口”选择“以题找文”或“以文找文”。前者填写研究问题；后者先上传或选择 1–3 篇种子论文。
3. 以文模式可以留空研究目标，也可填写“比较这篇论文的替代方法”“寻找空间关系建模的直接对比工作”等。上传支持文字型 PDF；扫描件尚无 OCR。每篇仍受现有 25 MiB 等解析限制。
4. 选择输出模式、年份和发表条件，开始研究。种子作为起点，不因发现文献的年份筛选而被排除；发现的新文献仍遵守条件。
5. 直接在网页阅读报告、方法对照与关联理由，点击引文或在线阅读核对保存文本。下载是可选的。

如果想查早期直接对比工作，不宜只限定最近一年。顶刊条件需要带来源和版本的认可名单，系统不会凭模型知识认定级别。

## 系统实际如何做

以文入口使用提取后的原文片段，而不是只拿 PDF 文件名搜索。最多 3 篇种子，每篇取前 3 页、每页最多 1200 字符、每篇累计最多 3000 字符；片段带物理页码、访问范围与文档哈希。它是有界检索线索，不能表示已经精读整篇论文，文件名也不等于已经认证的论文题名。

规划器先给出研究问题查询，再给出方法扩展查询。并发检索 arXiv/OpenAlex，记录来源、年份窗口、执行查询和失败。OpenAlex 的以文检索按相关度排序；候选经过元数据条件和分批模型相关性筛选。通过筛选后，优先保留第一条问题查询中的结果，再补充仅来自方法扩展的结果；各组内交错年份取样。查询出处只是排序线索，不是同问题的证明。

已确认身份的种子不计为新发现；文档 ID、内容哈希、DOI 和 arXiv ID 可用于识别。同一 PDF 首部出现唯一、显式的 DOI/arXiv ID 时辅助匹配；没有可靠标识或含多个标识时不猜测，因此仍可能存在跨来源去重遗漏。

检索检查点包含种子内容哈希、研究条件、模型及 Skill 版本。替换论文不会复用旧检索计划。失败查询可重试；全部论文源连接失败会显示来源不可用，不再当成“没有相关论文”。

## 报告应回答什么

报告主体围绕研究分支与脉络、方法与证据对照、重点阅读理由、选题切口与下一步。以文模式额外保留研究起点及“与种子论文关联”列。每篇论文尽量单独解读，再组成对照表，避免将不同领域摘要拼成未经验证的统一结论。具体显示结构取决于趋势或精读模式。

论文中“作者没有在摘要里提到”不等于“该领域没有做过”；方法相关不等于已经被种子引用、证明可迁移或是现成基线。关联理由是模型基于所见文本的判断，可能过度概括，必须与原文核对。系统目前没有实现可靠引用/被引图谱，不宣称这些结果是引用关系。

## 交付范围

这两种入口可以作为第一版完整主线。行业现况目前只覆盖学术研究视角；企业、市场、政策等行业情报还需要其他来源，不属于本轮完成范围。当前不新增向量数据库、引用图服务、模型下载或后台磁盘清理程序。正式报告质量评测与消融实验按用户要求后置。
